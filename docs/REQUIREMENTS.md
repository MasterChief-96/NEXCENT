## Таблицы и связи

| Таблица | Назначение и основные связи |
|---|---|
| `manufacturers` | Кухня/производитель → `products.manufacturer_id` |
| `categories` | Категория → `products.category_id` |
| `products` | Каталог; используется корзиной, избранным, строками заказов |
| `product_properties` | Свойства блюда → products; каскадное удаление |
| `product_images` | Фотографии блюда → products; каскадное удаление |
| `users` | Аккаунт и роль |
| `feedback` | Обращение/отзыв → users; при удалении пользователя FK обнуляется |
| `user_sessions` | Хэш токена сессии, CSRF, срок, JSON-состояние → users |
| `user_actions` | Журнал действий → users |
| `cart_items` | Состав корзины, составной PK user/product |
| `favorites` | Избранное, составной PK user/product |
| `orders` | Заказ → users; уникальный ключ повторной отправки |
| `order_items` | Снимок названия/цены/количества → orders/products |
| `restaurant_settings` | Общая вместимость; строка блокируется при создании брони |
| `bookings` | Бронь → users, дата UTC, число гостей, план ужина, статус |
| `schema_migrations` | Служебная история применённой схемы и checksum |

Архивирование блюда вместо физического удаления сохраняет историю заказов. Заказ создаётся в транзакции с блокировкой корзины пользователя; итог рассчитывается по текущим ценам из БД. Две одновременные заявки на оставшиеся места проходят последовательно через блокировку `restaurant_settings`, поэтому суммарная вместимость не превышается.

## Дополнительные улучшения

HttpOnly/SameSite cookies, Secure при HTTPS, смена идентификатора сессии после входа, CSRF, ограничения частоты запросов, CSP/Helmet, экранирование пользовательского HTML, ограничение размера JSON, подготовленные SQL-запросы, блокировка аккаунта с отзывом сессий, запрет отключения последнего администратора, управление статусами с проверкой переходов, Docker Compose, HTTPS через Caddy и резервное копирование.

## Границы подтверждения

Обязательное ознакомление с политикой проверяется и браузером, и API. Гостевая и пользовательская корзина отражаются в серверной сессии; при новом входе загружается существующая корзина аккаунта. Синхронизация не требует изменения схемы БД.

Пункт «поля по чек-листу Роскомнадзора» нельзя окончательно подтвердить без самого чек-листа и реальных реквизитов оператора. В `.env.example` добавлены настройки для заполнения реквизитов; исходная `.env` пользователя сохранена.
