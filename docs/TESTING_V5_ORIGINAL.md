# Проверка проекта

## Проверка версии 5.1 — 5 ноября 2026

- **25 из 25 интеграционных тестов прошли** на отдельной MariaDB 10.11 через mysql2. Первые 18 проверяют основной API; 7 новых — подтверждение политики, гостевую сессию и изоляцию корзин, восстановление корзины при входе, сохранение свойств/галереи/производителя, повторную инициализацию без изменения существующих строк, лимит поиска и реквизиты политики.
- Повторный запуск `scripts/init-db.js` проверен сравнением строк users (включая хэши паролей), products, product_properties, product_images, cart_items, feedback и restaurant_settings до и после. Данные не изменились.
- `scripts/backup.js --local` создал SQL/gzip-копию тестовой базы; архив распаковывается и содержит структуру и записи пользователей. Восстановление этой копии отдельно не проверялось. Docker-вариант команды подготовлен для MySQL 8.4, но здесь не запускался.
- В Chrome проверены добавление блюда гостем, изменение количества обычным вводом, сохранение количества и суммы после перезагрузки, поиск по названию и ограничение поля в 100 символов. Авторизованные сценарии этой версии проверены через API; полный сценарий `test/browser.cjs` в этой проверке не запускался.
- Синтаксис 24 JS/CJS-файлов проверен. Отсутствующих локальных ссылок на девяти HTML-страницах нет.
- Побайтно подтверждено сохранение пользовательской `.env`, добавленной фотографии, `compose.yaml` и `sql/001-schema.sql` относительно последнего присланного RAR.
- Проверки использовали только отдельную тестовую базу. Рабочая база пользователя не подключалась. MySQL 8.4 в Docker и нагрузочное тестирование в этой среде не проверялись.

Полный браузерный сценарий был выполнен при подготовке версии 5.0. Он обновлён под новые обязательные флажки и оставлен в проекте для повторного запуска.

## Повторный запуск API-тестов

Создайте **отдельную** базу `nexcent_test` и пользователя с правами только на неё. Установите `npm ci`. Передайте её параметры через переменные окружения или временную `.env` в отдельной копии проекта:

```dotenv
NODE_ENV=development
APP_ORIGIN=http://localhost:3000
DB_HOST=127.0.0.1
DB_PORT=3306
DB_NAME=nexcent_test
DB_USER=nexcent_test
DB_PASSWORD=пароль_тестовой_базы
```

```bash
npm run db:init
npm test
```

Имя базы обязано заканчиваться на `_test`. Тесты добавляют данные; не запускайте их с production-реквизитами. Для чистого повторного прогона можно пересоздать исключительно свою тестовую базу. Пароли и телефоны в тестах синтетические.

## Браузерные тесты

В этой же тестовой конфигурации запустите сервер `npm start`, затем в другом терминале:

```bash
npx playwright install chromium
npm run test:browser
```

Нужна отдельная тестовая БД и исходный каталог. Тест использует SQL-доступ к тестовой базе, чтобы назначить тестовому аккаунту роль администратора; к рабочей базе его применять нельзя. По умолчанию сайт — `http://localhost:3000`, снимки — `test-results/`. `BASE_URL`, `QA_SHOTS_DIR` и `PW_BROWSER_EXECUTABLE` позволяют изменить эти параметры. Для Linux могут потребоваться системные зависимости Chromium.

## Ручная проверка перед размещением

1. Создать аккаунт; выйти и войти по номеру с российским началом `8`.
2. Положить блюда в корзину до входа; войти, проверить перенос и изменить количество.
3. Оформить заказ; посмотреть его в кабинете и изменить статус в админ-панели.
4. Создать бронь; проверить дату по Москве; подтвердить и отменить тестовую бронь.
5. Оставить отзыв; убедиться, что до модерации он не виден публично; опубликовать с ответом.
6. Изменить цену блюда; проверить меню, главную и новый заказ. Старый заказ должен сохранить старую цену.
7. Сменить пароль, проверить завершение других сессий; обычный пользователь не должен получать данные admin API.
8. Проверить HTTPS, cookies, мобильное меню, фотографии, ссылку на политику и скачивание TXT.
9. Сделать резервную копию и восстановить её в отдельную тестовую БД.
