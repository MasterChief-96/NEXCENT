# Nexcent — ресторан с бэкендом, версия 5.1

**Если у вас уже есть аккаунты и рабочая база, начните с [UPDATE.md](UPDATE.md).** Обновление сохраняет прежние настройки и использует существующую базу. Команды создания базы и администратора ниже предназначены для первого запуска.

Полный проект: исходная тема сайта, Node.js 24 + Express 5 + MySQL 8.4, личный кабинет и админ-панель. Файлы Python для запуска не нужны. Открытие HTML двойным щелчком или через Live Server не запускает API — используйте сервер ниже.

## Что работает

- Регистрация, вход по email **или телефону и паролю**, выход, «Запомнить меня».
- Личный кабинет: имя/email/телефон, смена пароля, заказы, бронирования, обращения, история действий, просмотренные блюда, история поиска и завершение других сессий.
- Каталог из базы: поиск, категории, фильтр блюд без мяса/рыбы, избранное, карточки с аллергенами. Изменённые администратором цены сразу используются в меню и заказах.
- Гостевая корзина в браузере, перенос в аккаунт при входе, количество и удаление блюд, заказ на самовывоз. Итог считает сервер; цены сохраняются в заказе. Повторная отправка с тем же ключом возвращает тот же заказ.
- Конструктор ужина: расчёт на компанию, перенос всего набора в корзину и передача пожеланий к бронированию.
- Бронирования: дата/время по Москве, 1–12 гостей, пожелание к столу, план ужина. Проверка вместимости на пересекающиеся двухчасовые визиты; по умолчанию 40 мест. Отмена в кабинете, подтверждение администратором.
- Отзывы с оценкой, модерацией и ответами ресторана. Три явно помеченных примера не входят в средний рейтинг.
- Админ-панель: статистика, добавление/редактирование/архивирование блюд, поиск и сортировка, пользователи и роли, блокировка, заказы, бронирования, модерация и ответы.
- Фотографии вымышленной команды, три слайда на главной, адаптивность, дневная/вечерняя тема, согласие на дополнительные cookies, отдельная политика с открытием в новом окне и скачиванием.

**В исходном `nnexcent-v4(1).rar` было четыре HTML-страницы без отзывов и портретов. В этом архиве эти части добавлены. Старые файлы не нужно накладывать поверх новой версии.**

## Самый простой запуск: Docker Desktop

Для Windows установите Docker Desktop с WSL 2 и запустите его. Распакуйте архив целиком, откройте терминал **в папке с `compose.yaml`**.

1. Создайте настройки со случайными паролями. Если Node.js 24 установлен:

   ```bash
   node scripts/setup.js
   ```

   Если Node.js не установлен, выполните через Docker (работает в PowerShell и bash):

   ```bash
   docker run --rm -v "${PWD}:/work" -w /work node:24-alpine node scripts/setup.js
   ```

2. Запустите приложение и базу:

   ```bash
   docker compose up -d --build
   docker compose logs -f app
   ```

   При первом запуске скачиваются образы, создаются таблицы и добавляются блюда. После строки `Nexcent: http://localhost:3000` откройте **http://localhost:3000**. `Ctrl+C` прекращает просмотр логов, сам сайт продолжает работать.

3. Создайте своего администратора:

   ```bash
   docker compose exec app node scripts/admin.js
   ```

   Введите email, новый пароль дважды, имя и телефон. Пароль при вводе скрыт. Общего пароля администратора в проекте нет. Зарегистрированный ранее email для нового администратора не подходит — используйте отдельный адрес.

4. Войдите с этими данными через «Войти». Панель находится по адресу **http://localhost:3000/admin.html**. Обычного пользователя создавайте через форму регистрации.

Остановка: `docker compose down`. Повторный запуск: `docker compose up -d`.
База сохраняется в Docker volume. **Не добавляйте `-v` к `docker compose down`, если хотите сохранить данные.**

## Запуск без Docker

Нужны Node.js 24 и работающий MySQL 8.4. Сервер также проверен с MariaDB 10.11. Создайте базу и отдельного пользователя в вашей СУБД:

```sql
CREATE DATABASE nexcent CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'nexcent'@'localhost' IDENTIFIED BY 'ваш_случайный_пароль';
GRANT ALL PRIVILEGES ON nexcent.* TO 'nexcent'@'localhost';
```

Затем в папке проекта:

```bash
node scripts/setup.js
npm ci
```

Откройте `.env`, задайте `DB_HOST`, `DB_PORT`, `DB_USER`, `DB_PASSWORD`, `DB_NAME` по вашей базе. Дальше:

```bash
npm run db:init
npm run admin:create
npm start
```

Для разработки с перезапуском сервера: `npm run dev`. Файл `.env` содержит секреты: он не должен попадать в Git, переписку или публичную папку.

Обычный тариф для статических/PHP-сайтов подходит только если отдельно поддерживает постоянный Node.js-процесс и вашу базу. Для предоставленного Docker-проекта проще взять VPS. Пошаговое размещение, HTTPS и резервные копии — в [docs/DEPLOY.md](docs/DEPLOY.md).

## Где что менять

| Что | Где |
|---|---|
| Главная, о ресторане, контакты | `public/index.html`, `about.html`, `booking.html` |
| Оформление новых страниц | `public/assets/backend.css` |
| Фронтенд/API | `public/assets/backend.js`, `admin.js` |
| Основные маршруты | `server/app.js` |
| Сессии, cookies, CSRF | `server/auth.js` |
| Проверка данных | `server/validation.js` |
| SQL и начальный каталог | `sql/001-schema.sql`, `sql/products.json` |
| Подключение к БД | `.env`, `server/db.js` |
| Вместимость | `restaurant_settings.capacity` в БД, строка `id=1` |
| Документ политики | `public/privacy.html` и `public/privacy.txt` — обновлять оба |

Меню редактируйте через панель или непосредственно в БД. `sql/products.json` — только начальное заполнение; изменение этого файла не перезаписывает существующие блюда. `/assets/catalog.js` формируется сервером из БД, одноимённый статический файл — исходный резервный каталог.

Фотографии блюда выбираются из `public/assets`. Для новой загрузите файл WebP/JPG/PNG с именем латиницей без пробелов в эту папку, пересоберите контейнер приложения и обновите админ-панель. Веб-загрузка файлов не реализована.

## Важные границы этой версии

- Ресторан, команда и исходные контакты учебные. Перед публичной эксплуатацией замените их и заполните сведения об операторе и реальные условия в политике данных. Документ описывает приложение, но не является готовым юридическим заключением.
- Вход по телефону — **номер + пароль**. Подтверждение владения номером/email и SMS-коды не подключены.
- Заказы действительно записываются в БД. Онлайн-оплаты и доставки нет; предусмотрены самовывоз и оплата при получении.
- Уведомления доступны в кабинете и панели. SMS, email, Telegram, касса и CRM требуют отдельных провайдеров и ключей и не подключены.
- Восстановление забытого пароля выполняет владелец сервера: `docker compose exec app node scripts/admin.js --reset`. После смены все сессии этого пользователя завершаются. Для самостоятельного восстановления понадобится почтовый/SMS-провайдер.
- Бронь учитывает общую вместимость, а не схему конкретных столов. Время визита — 2 часа, заявки `pending` тоже занимают места. Администратор должен обрабатывать и отменять неактуальные заявки.
- Приложение рассчитано на один Node.js-процесс. Сессии лежат в БД; ограничение частоты запросов — в памяти процесса. Для нескольких экземпляров нужен общий rate-limit store и отдельная настройка инфраструктуры.
- Админ-списки показывают последние 500 пользователей/обращений/броней и 200 заказов; личные списки ограничены. Данные сверх лимита остаются в БД. Для большого проекта стоит добавить серверную пагинацию и выгрузки.

## Проверки

18 интеграционных сценариев проверены на настоящей MariaDB 10.11 через драйвер mysql2. Через Chromium проверены регистрация, перенос гостевой корзины, заказ, отзыв, бронь, поиск, кабинет, редактирование блюда и мобильные страницы; ошибок JavaScript не обнаружено. Docker Engine в среде разработки недоступен: контейнерный запуск MySQL 8.4 здесь не выполнялся.

`npm test` требует отдельную подготовленную базу с именем, оканчивающимся на `_test`; запуск на рабочей базе запрещён кодом тестов. Тесты записывают синтетические аккаунты и заявки. Подробнее — [docs/TESTING.md](docs/TESTING.md).
