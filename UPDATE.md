# Обновление до 5.1 без потери аккаунтов

В этом архиве сохранены ваша `.env` и добавленная фотография. Аккаунты, хэши паролей, заказы и другие записи находятся в MySQL, а не в исходниках. Дампа вашей базы в присланном RAR не было. Новая версия использует существующую схему; файл `sql/001-schema.sql` и имя проекта Docker Compose `nexcent` не изменены.

## Если сайт уже работает через Docker

Все команды выполняйте в **старой рабочей папке**, где находятся ваши `compose.yaml` и `.env`.

1. Сначала сохраните базу. Этот способ работает и без установленного Node.js:

   ```text
   docker compose exec db sh
   ```

   Вы окажетесь в оболочке контейнера базы. Выполните:

   ```sh
   umask 077
   MYSQL_PWD="$MYSQL_ROOT_PASSWORD" mysqldump -uroot --single-transaction --routines --triggers --hex-blob --no-tablespaces --set-gtid-purged=OFF "$MYSQL_DATABASE" > /tmp/nexcent-before-update.sql && echo BACKUP_OK
   exit
   ```

   После `BACKUP_OK`, уже в обычном терминале компьютера:

   ```text
   docker compose cp db:/tmp/nexcent-before-update.sql ./nexcent-before-update.sql
   ```

   Убедитесь, что файл скопирован и не пуст. Если выгрузка завершилась с ошибкой, сначала исправьте её. Для повторных обновлений сохраняйте предыдущие копии под отдельными именами.

2. Скопируйте файлы исправленного проекта в эту же рабочую папку с заменой. **Оставьте текущую `.env`, резервные копии и файлы базы.** В архиве `.env` совпадает с присланной вами, но на вашем компьютере могла появиться более новая настройка. Новую базу создавать не требуется.

3. Пересоберите только приложение, сохраняя запущенный контейнер базы:

   ```text
   docker compose up -d --build --no-deps app
   docker compose logs --tail=40 app
   ```

4. Откройте сайт, обновите страницу сочетанием **Ctrl+F5** и войдите под прежним аккаунтом. Повторно создавать администратора или сбрасывать пароль не нужно.

Для этого обновления не нужны `docker compose down -v`, удаление Docker volume, `DROP DATABASE` или импорт начальной схемы поверх рабочей базы.

## Если сайт работает без Docker

Остановите Node.js-приложение, оставив MySQL запущенным. Сохраните текущую `.env`. Для резервной копии можно скопировать новый `scripts/backup.js` в старую папку и выполнить из неё:

```text
node --env-file-if-exists=.env scripts/backup.js --local
```

Нужны Node.js 24 и `mysqldump` в PATH. Копия появится в `backups/*.sql.gz`. После успешной копии замените исходники, сохранив `.env`, и выполните:

```text
npm ci
npm start
```

Существующей базе не требуется повторная инициализация. После запуска проверьте прежний аккаунт и его заказы.

## Что исправлено

- Редактирование блюда сохраняет дополнительные свойства, их доплаты, производителя и галерею. Изменение основной фотографии добавляет её в галерею, сохраняя предыдущие фотографии.
- Гостевая корзина сохраняется в браузере и серверной сессии. Корзина аккаунта восстанавливается в сессии после входа и смены пароля; чтение корзины обновляет её снимок в текущей сессии.
- Обязательное ознакомление с политикой проверяется сервером отдельно от согласия на обработку. Проверки добавлены в регистрацию, обращения, отзывы, бронирование и заказ.
- Поиск ограничен 100 символами на клиенте и сервере. Уточнены ограничения формы регистрации.
- Ошибка соединения при запуске выводится без реквизитов подключения.
- Добавлено резервное копирование SQL в gzip через Node.js, без проблем с кодировкой PowerShell. После обновления: `npm run db:backup -- --docker` или `npm run db:backup -- --local`.

## Реквизиты политики

Реальные сведения об операторе в исходном проекте не указаны. Их нельзя достоверно заполнить автоматически. При необходимости добавьте в **свою существующую** `.env`:

```dotenv
LEGAL_OPERATOR_NAME="Полное имя или наименование оператора"
LEGAL_OPERATOR_ADDRESS="Адрес оператора"
LEGAL_CONTACT_EMAIL="Действующий email для обращений"
```

После перезапуска приложения значения появятся одновременно в `/privacy.html` и скачиваемой `/privacy.txt`. Без всех трёх значений остаётся явная пометка учебного проекта. Это возможность заполнить реквизиты, а не подтверждение соответствия неизвестному чек-листу Роскомнадзора: сам чек-лист в задании не приложен.

Старые записи о согласии и пароли пользователей не изменяются. Для новых регистраций версия политики записывается как `2026-11-05`.

## Проверка после обновления

Войдите прежним аккаунтом, проверьте заказы, добавьте блюдо в корзину, выйдите и войдите снова. В админке измените цену блюда с дополнительными свойствами и фотографиями: эти данные должны сохраниться. Отправьте тестовый отзыв и проверьте его в кабинете и на модерации.
