# Nexcent на Railway

Railway запускает сервис сайта по корневому Dockerfile. MySQL нужно создать отдельно в том же проекте и окружении. Файл `railway.json` задаёт команду `node scripts/start-railway.js` и проверку `/api/health`; вручную прописывать Start Command не требуется.

## 1. База и переменные сайта

Создайте MySQL через New → Database → MySQL (если его ещё нет). Дождитесь готовности базы. Откройте **сервис сайта**, затем Variables → Raw Editor. Для сервиса базы с точным именем `MySQL` добавьте:

```dotenv
DB_HOST=${{MySQL.MYSQLHOST}}
DB_PORT=${{MySQL.MYSQLPORT}}
DB_NAME=${{MySQL.MYSQLDATABASE}}
DB_USER=${{MySQL.MYSQLUSER}}
DB_PASSWORD=${{MySQL.MYSQLPASSWORD}}
SEED_DEMO_REVIEWS=false
```

Если сервис базы называется иначе, замените `MySQL` перед точкой. Не переносите пароль из старого Netrun-проекта: здесь используются реквизиты новой базы Railway. Переменные MYSQL* внутри сервиса базы сами по себе не появляются в сервисе сайта — нужны ссылки выше. Публиковать порт MySQL в интернет для сайта не требуется.

## 2. Администратор сайта

В Variables сайта отдельно добавьте `ADMIN_EMAIL`, `ADMIN_PASSWORD`, `ADMIN_NAME`, `ADMIN_PHONE`. Телефон в формате `+7XXXXXXXXXX`. Приложение принимает пароль от 8 символов, не более 72 байт UTF-8; используйте длинный случайный пароль. Не сохраняйте реальные пароли в GitHub.

Первый запуск создаёт администратора только при полностью пустой таблице users. После успешного входа удалите ADMIN_PASSWORD из Variables. Существующие аккаунты, пароли и роли не перезаписываются. Без ADMIN_PASSWORD создание администратора пропускается.

## 3. Адрес и запуск

В Settings → Networking сервиса сайта нажмите Generate Domain. Приложение использует PORT Railway (по умолчанию 3000). Если панель спрашивает целевой порт, укажите порт приложения.

Не задавайте APP_ORIGIN, если используете выданный Railway домен: скрипт берёт его из RAILWAY_PUBLIC_DOMAIN. Если раньше вставляли localhost или https://example.invalid, удалите эту переменную. Для собственного домена задайте APP_ORIGIN полным HTTPS-адресом без пути.

Скрипт Railway включает production и доверие одному обратному прокси. Он проверяет DB_*, ждёт MySQL при временных сетевых сбоях (до 30 попыток с таймаутом подключения 3 секунды и паузой 2 секунды), выполняет init-db.js и bootstrap-admin.js, затем запускает сервер. Ошибка пароля или отсутствующая база не маскируется бесконечными повторами. Миграции выполняются при запуске, когда доступна внутренняя сеть, а не при сборке образа.

Примените изменения Railway и опубликуйте последнюю версию main. В логе ожидаются «База готова» и «Nexcent: ...». Адрес localhost в последнем сообщении — техническая строка сервера; открывайте публичный HTTPS-домен Railway.

## 4. Диагностика и проверка

- «Задайте переменные» — добавьте DB_* в сервис сайта, не только в MySQL.
- ECONNREFUSED — проверьте готовность MySQL, хост и порт; 127.0.0.1 указывает на сам контейнер сайта.
- ENOTFOUND — проверьте точное имя сервиса в ссылках и одинаковое окружение сервисов.
- ER_ACCESS_DENIED_ERROR — неверные реквизиты пользователя базы.
- ER_BAD_DB_ERROR — неверное имя базы; берите MYSQLDATABASE из MySQL-сервиса.
- APP_ORIGIN — создайте домен; заглушка example.invalid в этом режиме запрещена.
- При ошибке старого запуска убедитесь, что публикация использует новый коммит и startCommand из railway.json.

Откройте /api/health (должно быть {"ok":true}), затем проверьте вход, каталог, корзину, заказ и бронь. Автотесты с созданием/удалением данных выполняйте только на отдельной тестовой базе (см. README.md). Старые отчёты qa не подтверждают успешную публикацию в Railway.

## Просмотр базы

Текущая конфигурация публикует сайт и использует отдельный MySQL. Она не разворачивает Netrun-сервисы web/adminer: адрес /adminer/ пока не настроен. Для браузерного Adminer потребуется отдельный сервис с защитой доступа; пароль администратора сайта не является паролем MySQL.

Официальные инструкции: https://docs.railway.com/databases/mysql и https://docs.railway.com/config-as-code/reference .
